# AI와 사람의 역할

이 저장소는 Claude Code로 만들었습니다. 무엇을 AI가 만들었고 무엇을 사람이 정했는지 나눠 적습니다.

## 사람이 정한 것
- 만들 범위: 기준 → 에이전트 테스트 → 판정 근거 → 배포 게이트 흐름만 작게 재현한다
- 대상: API 문서가 공개돼 있고 CI에서 안정적으로 돌릴 수 있는 Toolshop
- 에이전트 규칙의 내용: 기대결과 누락·과잉 검증 금지, 실제 화면 확인 후 구현, 실패를 숨기지 않기, 데이터 하드코딩 금지 (실무에서 쓰던 규칙을 일반화)
- 게이트 정책: blocker 실패·미판정은 No-Go, 재시도 0회
- 에이전트 구성: 작성(test-writer)과 검토(test-reviewer)를 나누고, 검토 에이전트는 읽기 전용. 실무에서 쓰던 6개 역할 분리(데이터 탐색, 이슈 조회, 작성, 리뷰, 결과 기록, 시트 반영) 중 이 저장소에 필요한 둘만 옮김

## AI가 만든 것
- 기준 초안(`criteria/toolshop.yaml`), 테스트 코드, 리포터, 게이트 스크립트, CI 설정
- 화면 요소 확인: Playwright로 실제 페이지를 열어 `data-test` 속성과 흐름을 확인한 뒤 테스트를 작성

## 실행 중에 AI가 하는 일
- 테스트가 끝나면 AI가 기준 문장과 판정 근거만 보고 다시 판정하고, 실패 원인을 분류한다(`scripts/ai-judge.mjs`)
- 코드 판정과 AI 판정이 다르면 게이트가 사람 검토로 돌린다. 최종 판단은 사람이 한다

## 사람이 검토한 것
- 기준 문장이 통과·실패를 모호하지 않게 정의하는지
- 테스트가 기준보다 많거나 적게 검증하지 않는지
- 게이트가 규칙대로 막는지 (`scripts/gate-selfcheck.mjs`)

## 결함 주입 빌드: 무엇을 잡았나

공식 결함 목록([listOfBugs.md](https://github.com/testsmith-io/practice-software-testing/blob/main/sprint5-with-bugs/testSessions/listOfBugs.md))과 대조했습니다. 기준은 결함 목록을 보기 전에 요구사항 관점으로 정했습니다.

| 기준 | 결과 | 공식 결함 |
|---|---|---|
| C-API-04 재고 수량 비노출 | 실패, 제품 결함 | 75번 상품 API가 재고 수량을 드러냄 |
| C-SEC-01 자기 송장만 조회 | 실패, 제품 결함 | 78번 다른 사용자 송장까지 반환 |
| C-SEC-02 무토큰 삭제 불가 | 실패, 제품 결함 | 76번 admin 토큰 없이 삭제 시도 가능(인증 대신 409가 먼저 반환) |
| C-EDGE-02 결과 없음 안내 | 실패, 제품 결함 | 목록에 없음. 결과 없음 문구가 나오지 않음 |
| C-UI-03·04·05, C-FLOW-01, C-I18N-01·02, C-EDGE-01·05 | 실패, 제품 결함 | 75번의 연쇄 영향. 재고 여부를 알 수 없어 검증 대상 상품을 고르지 못함 |
| C-EDGE-06·08 | 시간 초과, 테스트 문제 | 화면 구조가 달라 오류 문구 요소를 찾지 못함(87번 등 라벨 누락과 관련 추정) |

**놓친 것:** 21번(비밀번호 1회 오입력으로 잠김)은 C-EDGE-07이 통과했습니다. API 로그인은 잠기지 않고 화면 쪽만 잠기는 것으로 보입니다. 기준이 API만 보도록 정의돼 있어 잡지 못했습니다. 2번(정렬이 반대)은 카테고리 화면 결함이라 홈 화면 정렬을 보는 C-UI-06으로는 잡히지 않았습니다.

**배운 점:** 결함 하나(75번)가 기준 9개를 함께 막았습니다. 테스트가 대상 상품을 API로 고르기 때문입니다. 연쇄 실패는 원인이 한 곳이라는 신호라, 실패 개수보다 원인 개수로 보고하는 게 맞습니다.

## 환경 장애: 제품 결함과 구분했나

21개 실패 중 20개를 AI가 환경 문제로 분류했습니다. 1개(C-UI-06)는 정렬 요소를 찾지 못한 것을 테스트 문제로 분류했는데, 실제 원인은 API가 꺼져 상품 목록이 비어 있던 것이라 **오분류**입니다. 오류 메시지에 접속 거부가 직접 드러나지 않으면 AI도 환경 문제를 알아채지 못했습니다.

통과한 2개(C-EDGE-06 로그인 입력 검증, C-EDGE-08 문의 양식 필수값)는 서버 없이 화면에서 검증되는 기준이라 맞는 결과입니다.
